## 3. Risques et anomalies

| # | Gravité | Constat (preuve) | Conséquence | Correction proposée |
|---|---|---|---|---|
| R1 | ✅ Corrigé (GitHub Nooreyni/pointage) | Code **jamais poussé** sur un dépôt (`git remote` vide, 13 commits locaux) | Perte totale si la session cloud est recyclée | Rattacher un repo GitHub et pousser |
| R2 | ✅ Corrigé (migration 13) | Liaison compte ↔ personne **à la création du compte**, sans vérifier que l'e-mail est confirmé (`lier_compte`) ; inscription par e-mail ouverte par défaut sur Supabase | Quelqu'un peut créer un compte avec l'e-mail d'un collègue jamais connecté : la vraie personne est ensuite **bloquée** (« compte non reconnu ») | Lier uniquement un e-mail confirmé via Microsoft ; **désactiver l'inscription par e-mail** en production |
| R3 | ✅ Corrigé (`file.ts`) | File hors ligne en `localStorage` **non rattachée à l'utilisateur** (`file.ts`) | Sur un PC partagé, des pointages en attente sont rejoués **au nom du suivant** | Clé par personne + purge à la déconnexion |
| R4 | ✅ Corrigé (migration 14) | `pointer()` accepte une heure passée jusqu'à **72 h** depuis l'appli en ligne (prévu pour le hors ligne) | Un employé peut antidater son arrivée sans que le N+1 le voie (IP vide, lieu « inconnu ») | Marquer « pointage différé » visible N+1/RH, limiter aux synchronisations hors ligne |
| R5 | ✅ Corrigé (migration 12) | `cloturer_mois` n'exige pas que le mois précédent soit clôturé | Boni reporté sur une mauvaise période, soldes faux | Imposer l'ordre des clôtures |
| R6 | 🟠 Moyen | Récup et repos compensatoire en période **trimestrielle** sans report ni expiration ; congés N-1 non reportés | Au 1er jour du trimestre / de l'année, le solde affiché retombe à zéro | Règle à fixer (Dinclock / RH), puis report automatique |
| R7 | ✅ Corrigé (migration 14) | Base Supabase en **UTC** ; les tests locaux forcent Bruxelles (`run.sh`) | Entre minuit et 1–2 h, « aujourd'hui » = la veille côté serveur (présence, clôture, anomalies) ; écart test/prod | `alter database … set timezone 'Europe/Brussels'` |
| R8 | ✅ Corrigé (migration 12) | Max hebdo 45 h non contrôlé (paramètre inutilisé) | Non-respect d'une limite légale non détecté | Anomalie « semaine > 45 h » + alerte |
| R9 | ✅ Corrigé (migration 15 + fonction Edge) | Notifications générées mais **aucun envoi** (0 envoyée) | Rappels invisibles hors de l'appli → la RH continue d'appeler | Fonction d'envoi push + e-mail (M365) |
| R10 | ✅ Corrigé (paramètres lus) | Pause et heures par défaut **en dur** dans l'écran Pointer | Si la RH change la règle, l'affichage en direct diverge jusqu'à la sortie | Lire les paramètres serveur |
| R11 | ✅ Réglage `ip_visible_n1` | IP visible par le N+1 (vue `pointages`) | Question de proportionnalité RGPD | **Décision Ousmane** : IP réservée RH/admin ? |
| R12 | ✅ Corrigé (horloge figée) | Tests SQL dépendants des dates d'octobre-novembre 2026 | Faux échecs en rejouant plus tard (déjà arrivé une fois) | Dates relatives |
| R13 | ✅ Corrigé (CSV neutralisé) | Export CSV : pas de protection contre les formules (`=`, `+`, `@`) | Risque théorique (noms saisis par l'admin) | Préfixer les cellules à risque |
| R14 | ✅ Corrigé (actions des alertes) | Liens des notifications non cliquables | Confort | Navigation vers l'écran concerné |
| R15 | ✅ Corrigé (migration 16) | 21 clés étrangères sans index | Négligeable à 70 personnes | Indexer `demandes(code_absence)`, `personnes(service_id)` |

## 6. Suivi des corrections (31/10/2026, soir)
| # | Correction |
|---|---|
| R2 | Liaison compte ↔ personne seulement si l'identité est vérifiée : e-mail confirmé **et** connexion via le fournisseur d'identité (réglage `liaison_sso_seulement`, oui par défaut). Liaison aussi à la confirmation, au 1er accès (`lier_mon_compte`) et à l'enregistrement par l'admin. L'admin peut délier un compte ; une adresse corrigée délie l'ancien compte. 14 tests. **Reste à faire côté Supabase (tableau de bord)** : désactiver l'inscription par e-mail en production. |
| R3 | File hors ligne **par personne** (`cfb.pointages-en-attente:<id>`), jamais rejouée au nom d'un autre ; ancienne file sans auteur supprimée ; à la déconnexion hors ligne, avertissement (les pointages restent au nom de leur auteur et partent à sa prochaine connexion). 5 tests unitaires + parcours navigateur. |
| R4 | Pointage à une heure passée accepté **uniquement** depuis la synchro hors ligne (identifiant d'appareil obligatoire), heure future refusée. Marqueur « différé » (+ délai en minutes) visible de l'employé, du N+1 et de la RH ; IP non enregistrée. Délai maximal (`differe_max_h`, 72 h) et alerte au N+1 (`differe_alerte_n1_min`, 60 min, 0 = jamais) réglables. 8 tests. |
| R7 | Le calcul ne dépend plus du fuseau du serveur : toutes les fonctions s'exécutent en Europe/Brussels, les vues utilisent `pointage.aujourdhui()`, et la base Supabase est réglée sur Europe/Brussels. | R9 | Envoi réel des notifications : push Web (VAPID, chiffrement RFC 8291 vérifié sur le vecteur officiel) sur chaque appareil, e-mail de secours Microsoft 365 si aucun appareil ne reçoit (si configuré), reprises toutes les 5 min, abandon après 5 essais ou 24 h, appareils expirés supprimés. Réveil immédiat par la base (pg_net). Testé de bout en bout sur Supabase dev. Activation par chacun dans Alertes / bandeau Pointer ; désactivée à la déconnexion (appareil partagé). |
